# محافظ إلكترو — Next.js

نسخة Next.js (App Router) من الموقع، معمولة أساسًا عشان تحل مشكلة السيو اللي كانت
في نسخة الـ HTML الواحدة: كل منتج دلوقتي عندو رابط حقيقي (`/products/nova-x200-pro`
مثلاً) قابل للفهرسة من جوجل، بدل روابط `#/` اللي كانت مش بتبان لمحركات البحث.

## التشغيل محليًا

```bash
npm install
cp .env.local.example .env.local   # وبدّل الباسورد جوه
npm run dev
```

افتح http://localhost:3000

## هيكل المشروع

- `app/page.js` — الصفحة الرئيسية (Server Component، مفهرسة بالكامل)
- `app/products/page.js` — كل المنتجات، فلترة وبحث شغالين حتى من غير JavaScript
  (روابط ونموذج GET عادي)
- `app/products/[slug]/page.js` — صفحة كل منتج، فيها عنوان ووصف SEO مخصصين
  (`generateMetadata`) + بيانات `Product` منظمة (JSON-LD) لجوجل
- `app/admin` — لوحة التحكم (محمية بكلمة مرور من `.env.local`)
- `app/api/*` — نقاط API لإدارة المنتجات، الليدز، السوشيال ميديا، وتتبع النقرات
- `data/*.json` — قاعدة بيانات بسيطة على شكل ملفات JSON
- `app/sitemap.js` و `app/robots.js` — خريطة الموقع وملف الروبوتس بيتولّدو أوتوماتيك
  من نفس بيانات المنتجات

## قبل النشر (مهم)

1. **بدّل الدومين**: فيه أماكن مكتوب فيها `https://YOUR-DOMAIN.com` في
   `app/layout.js`, `app/sitemap.js`, `app/robots.js` — بدّلها بدومينك الحقيقي.
2. **بدّل رقم واتساب والروابط**: من `data/social.json` أو من لوحة التحكم مباشرة.
3. **بدّل الباسورد**: في `.env.local` غيّر `ADMIN_PASSWORD` لباسورد قوي.
4. **⚠️ لو هتستضيف على Vercel أو أي منصة serverless**: الكتابة على ملفات
   JSON في `data/` **مش هتتحفظ بشكل دائم** لأن نظام الملفات عندهم للقراءة فقط
   في بيئة الإنتاج (غير مجلد `/tmp` المؤقت). يعني لوحة التحكم (إضافة/تعديل
   منتجات، الليدز) هتشتغل بس مؤقتًا وهترجع للحالة الأصلية بعد كل نشر جديد.
   للاستخدام الحقيقي المستمر، عندك خيارين:
   - تستضيف على سيرفر عادي (VPS) بدل serverless، وتشغل `npm run build && npm start`.
   - أو (الأفضل على المدى الطويل) تستبدل ملفات JSON بقاعدة بيانات حقيقية
     (مثلاً Postgres على Supabase/Neon، أو SQLite مع قرص دائم).
5. **الأمان**: الباسورد بقى في متغير بيئة مش في الكود، والجلسة كوكي httpOnly —
   أفضل من النسخة السابقة بكتير، لكن لو أكتر من موظف هيدخل الإدارة، الأنسب
   نظام مستخدمين حقيقي (NextAuth أو مشابه).

## أفكار تحسين لاحقة

- صور حقيقية للمنتجات بدل الأيقونات (استخدم `next/image` للسرعة)
- صفحة "من نحن" وصفحة سياسة الاسترجاع
- ربط Google Search Console بعد النشر لمتابعة الفهرسة فعليًا
